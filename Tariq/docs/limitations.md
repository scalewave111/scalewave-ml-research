# What remains uncertain

| Issue | What we can say | What we cannot claim |
| --- | --- | --- |
| Magnitude improvement | Lower error on the same saved development population | Future profitability, significance or global optimum |
| Timing short-horizon gains | Small positive average changes in saved receipts | Stable gains on new data |
| Long-horizon cheap-screen leads | Some individual binned models beat baseline retrospectively | Confirmed winners or selected-tree policy success |
| Feature coverage | 386 candidates had usable sampled values | Full-period eligibility or predictive usefulness |
| Feature causality | Upstream timing needs more evidence | Proven leakage or proven leakage-free inputs |
| Timing replay | Saved score arithmetic and selection can be checked | Independent raw-data or fitted-model replay from this package |
| Pruned magnitude experiments | Compact scores/history survive | Every old binary or prediction remains available |
| Runtime engineering | Read each receipt's exact scope and pending flags | Every change was independently proven in a full cloud run |
| Runtime estimates | Historical planning aids | Guaranteed future completion times |
| Connected models | Allowed future direction | An implemented or validated multi-model system |

Historical verification files are immutable evidence about their original runs. They are not new verification of every file currently on disk. Old input_hashes.json files may refer to the incumbent before a later promotion, or to intentionally pruned files. The packaging manifest records current availability separately.
